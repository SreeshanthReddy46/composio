# Evaluation Rubric: SaaS Toolkit Buildability Ground Truth

This document defines the strict, unambiguous criteria for marking an agent's extracted field as **CORRECT** or **INCORRECT** against human gold annotations.

---

## Field-by-Field Criteria

### 1. `category`
- **Definition**: The primary SaaS operational domain.
- **Correctness Rule**: Must match the official primary taxonomy of the platform (e.g. `Productivity`, `CRM & Sales`, `Developer Tools`).
- **Evidence**: Homepage header, company about page, or developer documentation title.

### 2. `one_liner`
- **Definition**: Concise, factual 1-sentence summary of the product's primary utility.
- **Correctness Rule**: Must accurately capture the core business capability without promotional marketing hyperbole.

### 3. `auth_methods`
- **Definition**: Authentication mechanisms supported by the developer API.
- **Allowed values**: `oauth2`, `api_key`, `basic`, `bearer_token`, `jwt`, `other`, `none`, `unknown`.
- **Correctness Rule**: Must identify all primary authentication mechanisms mentioned in the official authentication reference page. If the API supports OAuth2 and Personal Access Tokens, both `oauth2` and `api_key` / `bearer_token` must be present.

### 4. `self_serve`
- **Definition**: Developer accessibility barrier to obtain working API keys/tokens.
- **Allowed values**:
  - `free_self_serve`: Any developer can register and generate working API credentials instantly without entering credit card details or awaiting human approval.
  - `trial_self_serve`: Self-serve access is provided during a limited free trial or requires credit card upfront.
  - `paid_required`: Requires an active paid subscription or purchased credits to generate or call API credentials.
  - `approval_required`: Requires submitting an application, business verification, developer account review, or partner vetting.
  - `partnership_or_sales_gated`: No public developer console; requires enterprise sales contact, contract negotiation, or invite-only partnership.
  - `unknown`: No documentation exists regarding developer onboarding.
- **Correctness Rule**: Strictly determined by the onboarding path documented on the developer portal or pricing FAQ.

### 5. `api_style`
- **Definition**: Architectural paradigm of the web API.
- **Allowed values**: `rest`, `graphql`, `soap`, `cli`, `none`, `unknown`.
- **Correctness Rule**: Must reflect the primary publicly exposed protocol. If both REST and GraphQL exist, `rest` or `graphql` is acceptable if noted.

### 6. `api_breadth`
- **Definition**: Surface area and completeness of the API.
- **Allowed values**:
  - `small`: Fewer than 15 endpoints or single narrow capability.
  - `medium`: 15 to 80 endpoints covering core platform workflows.
  - `large`: 80+ endpoints providing comprehensive coverage of all UI actions.
  - `unknown`: Documentation obscured behind login.

### 7. `existing_mcp`
- **Definition**: Availability of a Model Context Protocol (MCP) server.
- **Allowed values**: `official`, `community`, `none`, `unknown`.
- **Correctness Rule**:
  - `official`: Published or maintained by the vendor or Model Context Protocol organization (`modelcontextprotocol/servers`).
  - `community`: Published on GitHub/Smithery with active commits and public repo.
  - `none`: No functional MCP server exists.

### 8. `sandbox_available`
- **Definition**: Isolated test/sandbox environment separate from production data.
- **Allowed values**: `true`, `false`, `null`.
- **Correctness Rule**: `true` only if vendor provides a documented sandbox, test mode (e.g. Stripe test keys), or dedicated staging environment.

### 9. `openapi_spec_available`
- **Definition**: Public, machine-readable OpenAPI / Swagger JSON/YAML document.
- **Allowed values**: Valid URL pointing to `.json`/`.yaml`, `true` with documentation proof, or `false`/`null`.
- **Correctness Rule**: HTML documentation generated by Swagger UI does *not* count unless raw spec download is accessible.

### 10. `webhooks`
- **Definition**: Native HTTP callback event streaming.
- **Allowed values**: `true`, `false`, `null`.
- **Correctness Rule**: `true` only if documentation contains a dedicated Webhooks/Events guide for subscribing to outbound triggers.

### 11. `rate_limits_note`
- **Definition**: Documented request throttling thresholds.
- **Correctness Rule**: Must accurately cite requests-per-second (RPS), requests-per-minute (RPM), or daily call quotas.

### 12. `free_tier_note`
- **Definition**: Viability of operating API integrations on an unpaid plan.
- **Correctness Rule**: Must accurately state whether free-tier users can call the API or if paid plans are mandatory.

### 13. `in_composio_already`
- **Definition**: Toolkit already supported in Composio's official catalog (`https://composio.dev/tools` or SDK toolkits).
- **Correctness Rule**: Verified against Composio documentation.

### 14. `verdict`
- **Definition**: Buildability decision for Composio integration.
- **Allowed values**:
  - `ship_now`: Open API, self-serve credentials, standard REST/GraphQL/OAuth2, no blocking hurdles.
  - `ship_with_setup_friction`: Can be built, but requires user to create custom developer app or trial credentials.
  - `skill_or_cli_only`: No clean REST API, but automatable via CLI, MCP, or local tool.
  - `needs_outreach`: Requires partnership agreement, custom scopes, or sales contact.
  - `blocked`: No API exists, strict anti-bot detection, or actively hostile to third-party integrations.

### 15. `main_blocker`
- **Definition**: Primary impediment to integration (or "none").
- **Correctness Rule**: Concise statement explaining why verdict is not `ship_now`.

### 16. `difficulty_1_to_5`
- **Definition**: Estimated engineering effort to produce a production-grade Composio toolkit.
- **Scale**:
  - `1`: Trivial API key, clean OpenAPI spec, standard JSON REST.
  - `2`: Standard OAuth2, good documentation, well-behaved REST API.
  - `3`: Complex pagination, tricky token refreshes, rate limit nuances.
  - `4`: High-friction developer onboarding, XML/SOAP, bespoke webhook signing.
  - `5`: Closed enterprise sales gate, compliance audits, or reverse-engineered scraping needed.
